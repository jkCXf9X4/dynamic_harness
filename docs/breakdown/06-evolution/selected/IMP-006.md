# IMP-006: Maintain Traceability Map as a Living Register

## Lifecycle Stage
Proposed

## Status
Open

## Layer
Evolution

## Theme
Keep the traceability map (Claim/Need → Decision Record(s) → Artifact(s)) current
as a living document, so every claim stays traced to the decisions and artifacts
that realize it. The decision-log half of this IMP is **superseded**: every
DL-1…DL-17 row now has a record or state home, `decision-log.md` was retired to
`deprecated/` (2026-10-02), and the log is generated (`design-choice-log.md`).

## Evidence
- `breakdown_structure_critical_review.md` (the review that motivated this restructuring): GAP-1 "No decision records / no decision log" — "zero ADR files, zero decision-log files anywhere in the repo; ~10 real decisions exist only as prose; INVESTIGATION.md:9 points to a nonexistent log"; GAP-2 "No traceability map" — "REQ-1..15, G1–G13, VISION pillars, success criteria all unlinked"; the skill's rule "every new/edited record MUST be reflected in the decision log" is vacuous with no log.
- The dangling reference: `../investigations/multi-agent-coordination/INVESTIGATION.md` front-matter says "Parent-mediated relaying (option A) is rejected — see decision log" — the log did not exist when written (now it does: AD-001 + the decision log).
- The review's Part 2 drafted 15 decision-log rows (DL-1..DL-15) and a traceability map as *proposals* — "the draft registers are proposals, not records that exist in the repo. They should be reconciled against the actual code/commit history before being adopted as canonical" (caveat 3).

## Current Pain Or Risk
Without living registers, the ADRs and IMPs created by this restructuring decay back into the state the review found: decisions become prose again, cross-references dangle (the "see decision log" case), and the V-model promise ("every output traced to a requirement") is unfulfilled at repo level. A future run cannot tell what is decided vs proposed vs abandoned, so the same design space gets re-searched — violating the repo's own ground rule. Registers are only valuable if *kept current*; a stale log is worse than none (it misleads).

## Proposed Improvement
Maintain the traceability map (Claim/Need → Decision Record(s) → Artifact(s))
as a living register under `docs/breakdown/` — one row per claim/need →
decision record(s) → artifact(s) — updated whenever a claim, decision record,
or IMP changes status. Enforce the skill's rule: every new/edited record MUST
land in the decision stream, and the traceability map MUST stay current.

## Risk And Blast Radius
Low. Risk: the traceability map goes stale (the failure this IMP exists to prevent) or becomes ceremony with no enforcement. Blast radius: documentation only — no runtime code. Mitigation: keep it lean (one row per link, no duplication — the repo's information-hygiene principle), and make the update rule part of the ADR/IMP workflow rather than a separate process.
