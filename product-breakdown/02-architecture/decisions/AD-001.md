# AD-001: Reject Parent-Mediated Relaying for Collaboration

## Status
Accepted (rejection recorded)

## Layer
Architecture

## Context
Moving from *complicated* development (parallel decomposition into independent
sub-parts) toward *complex* development (a parent stands up children that
communicate and solve problems together) requires choosing a collaboration
topology. Option A — parent-mediated relaying, where all child↔child
interaction is relayed through the parent via `stream_children` + `converse` —
was the candidate that best fit the existing actor model, but it was rejected.

Documented in:
- `product-breakdown/02-architecture/multi-agent-coordination/INVESTIGATION.md`
  §"A. Stay parent-mediated — ❌ REJECTED" and the front-matter summary
  ("Parent-mediated relaying (option A) is rejected — see decision log").
- Empirically confirmed by
  `product-breakdown/04-verification/communication-structures/FINDINGS.md` and
  `product-breakdown/04-verification/communication-structures/RESULTS.md` (real-LLM benchmark, 2026-09-18, deepseek-v4-flash).

**Rationale basis:** the rejection rationale is DOCUMENTED (quoted verbatim in
the INVESTIGATION's "Why rejected" paragraph); the empirical deadlock evidence
is DOCUMENTED in FINDINGS/RESULTS. What is INFERRED is only that these together
are what the missing decision-log entry "would have said" — the INVESTIGATION
deferred to a decision log that did not exist at the time (now this record).

## Decision
Parent-mediated relaying (option A) is **rejected** as the collaboration
mechanism. The parent must not relay child↔child content. Collaboration is
enabled through a topic-channel / workspace-primary communication layer with
bounded message exceptions (see AD-002, AD-003), where the parent *introduces*
and *oversees* but never *relays*.

## Alternatives Considered
- **A. Stay parent-mediated (enhance `stream_children` + `converse`)** — all
  child↔child interaction relayed through the parent. REJECTED.
- **B. Sibling mailbox** — direct peer-to-peer messaging between children.
  Adopted in curated form (B-curated: common-parent scoping, see AD-002).
- **C. Team/panel (bounded shared workspace + chair)** — shared artifact
  workspace with a designated chair. Adopted as the workspace substrate in the
  hybrid channel decision (AD-003).

## Consequences
**Positive:**
- The orchestrating parent does not degrade into a monolithic agent as
  coordination grows — the exact cost the architecture was built to avoid.
- No mixed-context pollution: child settlements and converse replies no longer
  enter the parent context and cross-contaminate other branches.
- Empirically validated: the `off` (relay-style) cell **deadlocked** on
  circular blocking `converse` calls (0 turns, 900s watchdog timeout), while
  the `shared` channel cell completed correctly in 40 turns / 389s
  (FINDINGS.md "Deadlock: circular converse blocks the whole tree — CONFIRMED").

**Negative:**
- Requires relaxing the actor-model isolation invariant in a *bounded, curated*
  way (siblings gain a scoped communication surface) — see AD-002.
- New churn/looping surface (A↔B↔A cascades) needs its own cycle detection
  (per-pair counters, REQ-9).
- The runtime must track sibling edges in addition to parent→child edges.

## Verification
- Real-LLM benchmark (P4, 2026-09-18): the relay-style `off` cell deadlocked
  (timed_out, 0 turns, 900s watchdog); the `shared` channel cell completed
  correctly (40 turns, 389s, ~0.8M tokens). See FINDINGS.md + RESULTS.md +
  metrics-cells.json (all in `product-breakdown/04-verification/communication-structures/`).
- Re-verification pending: more replicates (n=1 per cell today) — see IMP-001.

## Review Trigger
Revisit if a bounded, lock-safe `converse` (e.g. bounded wait for the target's
next assistant message instead of the target's whole re-run) removes the
deadlock mechanism, or if a topology measurement shows parent-relay beating
channel topologies on cost/quality at scale.
