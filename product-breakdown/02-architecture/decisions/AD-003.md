# AD-003: Collaboration Channel = Workspace-Primary, Messages-as-Exception

## Status
Accepted

## Layer
Architecture

## Context
With the group defined (AD-002), the remaining open design choice is the
**collaboration channel**: do introduced siblings exchange via peer *messages*
(B-curated) or via a shared *workspace* (C)? The management-theory material
plus two additional theories researched for this decision provide a strong
anchor: media richness (Daft & Lengel), boundary objects (Star & Griesemer),
blackboard/distributed AI (Hearsay-II lineage), and modern collaborative
engineering practice (git / PR / code review).

Documented in:
- `product-breakdown/02-architecture/multi-agent-coordination/INVESTIGATION.md`
  §"Channel decision: shared workspace vs sibling messages" and
  §"The decision: workspace-primary, messages-as-exception".
- `product-breakdown/02-architecture/multi-agent-coordination/management-theory-communication-facilitation.md`
  (Shannon, Coase/Williamson transaction costs, Simon bounded rationality,
  Netflix "context over control", Hackman, McChrystal).

**Rationale basis:** DOCUMENTED — the decision and its four decision rules are
stated explicitly, anchored in the cited theories.

## Decision
The collaboration channel is a **shared, scoped workspace** (a sibling-visible
artifact area) as the primary substrate; **peer messages are the scarce,
bounded exception** used only for *equivocal* coordination. Decision rules:

1. **To share a result, finding, or constraint → write/read the workspace.**
   The artifact is the boundary object; "coordination without consensus"
   applies.
2. **To route or ask "who knows this?" → a message that points to the
   workspace** (ID + why), not a payload (mirrors REQ-4). TMS retrieval.
3. **To reconcile conflicting interpretations / demand a revision → messages**,
   the rich channel, but bounded per-pair and hard-stopped on over-budget
   (REQ-6, REQ-9) when the exchange should escalate to the parent or a fresh
   worker.
4. **Default source of truth is the workspace.** If a child that read the
   artifact disagrees with a sibling's message, the artifact wins; escalate if
   it matters (REQ-12, existing VERIFY).

## Alternatives Considered
- **B-curated pure (peer messages as the channel)** — REJECTED as the primary
  substrate: direct negotiation between specialists is the *worse* path per
  boundary-objects literature (pre-stabilization direct negotiation is
  "frustrating" and escalates friction); messages are interruptive (push) and
  consume recipient context.
- **C pure (shared workspace only, no messages)** — REJECTED as the sole
  channel: equivocal coordination (ambiguity, negotiation, "why is this
  wrong?") needs rich media with fast feedback; too-lean media for equivocal
  tasks causes more difficulties than too-rich media for lean tasks.
- **A (parent-mediated relaying)** — REJECTED (AD-001).

## Consequences
**Positive:**
- The parent relays nothing (messages and artifacts both bypass it).
- Recipient context is protected: most coordination is *pull* (read what you
  need) rather than *push* (interruptive message) — attacks the exact
  "mixed-context pollution" that killed option A, one level deeper.
- Churn/loop risk shrinks: the bounded message channel sees only equivocal
  exchanges; the workspace is naturally asynchronous and non-interruptive.
- Anchored in practice: workspace-first + bounded message-exception is exactly
  how git-team coordination and blackboard architectures work.

**Negative:**
- Workspace mechanics are undefined: a scoped `ArtifactStore` area needs
  write-conflict conventions and visibility rules the store does not enforce
  today (C's known gap) — open item, see IMP-002.
- Cadence/round semantics are undefined: "which children are waiting on a
  sibling's write" is a new lifecycle question — open item, see IMP-002.
- Equivocality is judged by the model: needs a stated heuristic (bias
  workspace-first by default) — open item, see IMP-003.

## Verification
- Comms benchmark: the `shared` cell (one topic channel, non-blocking
  post/channel_read) completed the interdependent collab task correctly in
  40 turns / 389s / ~0.8M tokens — the cell where the "shared log" matches the
  collaboration pattern (FINDINGS.md reading 2).
- `tests/backend/test_comms.py` + `tests/backend/test_comms_benchmark.py`.
- Pending: workspace mechanics (IMP-002) and equivocality heuristic (IMP-003)
  to make the decision rules executable.

## Review Trigger
Revisit if the workspace-primary rule proves wrong for a measured pattern
(e.g. a collaboration task where message-mediated negotiation dominates), or
if the equivocality heuristic (IMP-003) shows the model cannot reliably
distinguish equivocal vs uncertain coordination.
