# AD-006: Spine = Runtime `_links` + Reuse of Converse/_inject_queue + Artifact/Result Pointers; Spec Demoted to Advanced Policy Layer

## Status
Accepted

## Layer
Architecture

## Context
The collaboration-setting spec over-modeled. The advanced features (team
object, charter, norms, sanctions, workspace, arbitration ladder) are policy
layers that can sit on a much smaller spine — and the spine is mostly
*existing machinery*. A simplicity review distilled the architecture to three
primitives, all present in the codebase today.

Documented in:
- `product-breakdown/02-architecture/multi-agent-coordination/INVESTIGATION.md`
  §"Simplicity review: the spine — links + delivery + pointers" and
  §"What this removes from the spec".
- `product-breakdown/02-architecture/multi-agent-coordination/collaboration-setting-spec.md`
  (front-matter: "status: draft — ADVANCED LAYER (see INVESTIGATION.md
  'Simplicity review', the spine)").

**Rationale basis:** DOCUMENTED — the spine design, the comparison table, and
the demotion of the spec are stated explicitly.

## Decision
The collaboration architecture is a **three-primitive spine**, and the
collaboration-setting spec is **demoted to the advanced policy layer** (its
AC-1..11 still hold, but as *policy-layer* acceptance on top of the spine):

1. **Links** — ONE new structure: a runtime registry of authorized peer pairs
   (`self._links: set[tuple[str, str]]`, unordered, normalized). The *only*
   authorization rule: a `link(a, b)` call is accepted iff the caller is the
   common parent of both (`a.parent is caller and b.parent is caller`). No team
   object, no membership dict, no lifecycle FSM: membership *is* the link set,
   authorization *is* the parent-of-both check (O(1) via `target.parent`).
2. **Delivery** — reuse the existing message path: `converse` →
   `continue_with_input` → `_inject_queue`/`_inject_event`. A sibling message
   is just a `converse` whose eligibility gate becomes `(agent_a, agent_b) in
   self._links` (in addition to today's parent↔child). Summary-only,
   pointer-carrying: `[sibling {id}] {summary}\nPointer: {artifact_id|result_id}`.
3. **Content** — reuse existing pointer machinery: the recipient pulls the
   full body via `read_artifact` / `result_read`. **No workspace needed for
   MVP**: artifacts/result snapshots are already shared, immutable,
   display-scoped state; the missing piece was only *discovery* ("who produced
   what"), which the pointer in the message provides.

Lifecycle is free: `link` edges die implicitly when the parent settles
(deleting the subtree), or via `disconnect(a, b)`; no disband ceremony needed.

## Alternatives Considered
- **The full spec as core** (Team object, `TeamStatus` FSM, membership dict,
  charter object, workspace path-values-scoping, sanctions records as core) —
  REJECTED as core: days of work vs hours; the advanced processes compose on
  the spine (streaming children, broadcast/group via all-pairs links, loop/cost
  control via per-link counters, MAC catalogue, charter + mechanical verify,
  L2 arbitration, nested/recursive, resume/recovery).
- **A new TeamMailbox / scoped workspace dir as core** — REJECTED for MVP:
  existing `_inject_queue` and ArtifactStore/ResultStore + pointers already
  provide delivery and shared state; the missing piece was discovery only.

## Consequences
**Positive:**
- Enforcement shrinks to: link registry + an eligibility check in one place
  (converse path) + a counter. The rest is design intent, not mechanism.
- Time to value: hours, not days (new files: `policies/links.py`, tiny).
- Composes with advanced processes: the table in the INVESTIGATION shows each
  advanced feature mounting on the same primitive (e.g. broadcast = O(n²)
  macro over the same link primitive; G1 mechanical verify = a `verify` policy
  inspecting pointer targets at settlement — no core changes).
- Resume/recovery is free: links reference agent ids; a resumed child re-uses
  the live registry (no per-agent state to restore).

**Negative:**
- The advanced layer (workspace mechanics, cadence, sanctions UI) is deferred —
  the spec's AC-1..11 are not yet executable in code (see IMP-002, IMP-003,
  IMP-004).
- The spine's summary-only, pointer-carrying delivery assumes the recipient
  pulls content; a pattern needing push of full content is not covered by the
  MVP.
