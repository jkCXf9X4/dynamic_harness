# AD-007: Plugin Direction = Interface Economy (~7 Seams), No Loader / Late Injection

## Status
Accepted

## Layer
Implementation

## Context
The harness is a monolith of *near-seams*: tools grouped by concern, policies
extracted into host-agnostic decision objects, a metric-reactive registry that
already calls itself "the plugin seam", an event bus, an LLM provider ABC. Each
surface is individually extensible in code — but the seams are *incidental*:
their shapes differ, their breadth varies, and components still reach across
them. The seed suggestion asked for a common interface for metric-reactive
policies to "facilitate the move towards a more plugin centric architecture".

Documented in:
- `product-breakdown/03-implementation/plugin/INVESTIGATION.md` (Q1–Q7
  decisions, §Resolved rulings, §Success criteria).
- `product-breakdown/06-evolution/backlog.md` (the seed
  suggestion, PICKED UP as `ReactivePolicyRegistry`).
- `../../00-intent/platform-evaluation.md` (the core worth porting is the ~25-tool
  tool-execution + spawn layer).

**Rationale basis:** DOCUMENTED — the interface-economy goal, the Q1–Q7
rulings, and the "no loader" ruling are stated explicitly.

## Decision
Make the codebase plugin-*ready* by establishing a **small, stable set of ~7
narrow common interfaces** and decoupling/isolating components behind them —
**without** building a plugin architecture (no loader, no late code injection,
no manifest schema, no directory scanning, no entry points, no activate/
deactivate lifecycle). The target common-interface set:

1. Tool call contract — `ToolDef` / `ToolResult` / `ToolContext` + `ToolRegistry`
2. Metric-reactive policy — `Observation` / `PromptInjection` / `ReactivePolicy` / `ReactivePolicyRegistry` (the reference model)
3. Decision-policy objects (host-agnostic, import no agent/runtime)
4. Event bus — `EventBus` + event payload types
5. LLM provider — `LLMProvider` ABC + response/call types
6. Agent-class registry — `register_agent_class` / `delegate(agent_type=)`
7. Persistent data types — `Task` / `ReportPayload` / `Artifact` / `Commit` / `AgentOutcome` (pure Pydantic)

Supporting rulings: Q1 purpose = internal-structure enabler (external porting
out of scope); Q3 crash loudly, never silently swallow a broken component; Q4
safety invariants frozen (policies replaceable, safety frozen, tools/agent
classes additive); Q5 code-only config; Q6 no stdlib descriptor conversion;
Q7 no discovery, ever — component lists are explicit or default, never
scanned. `ToolContext` stays ONE contract, narrowed (faceting rejected — it
would multiply the interface count); policy application is registry-delegated
for shared concerns and tool-embedded policy objects for domain guards.

## Alternatives Considered
- **A. Loader / late-injection plugin architecture** — REJECTED (OUT OF
  SCOPE): "a loader is machinery that buys nothing until the seams are already
  minimal"; a plugin architecture with late injection of code is not required —
  plugin-ready *structure* is the target. (If contracts prove stable much
  later, a loader could sit on top — `../../00-intent/platform-evaluation.md` territory.)
- **C. Two-worlds (internal seams + external transport)** — REJECTED here (OUT
  OF SCOPE): serving the decision layer behind an MCP/third-party-host
  transport belongs to `../../00-intent/platform-evaluation.md`; B enables C later.
- **Faceted ToolContext** — REJECTED: faceting would multiply the
  common-interface count, contradicting the primary goal ("minimize common
  interfaces").

## Consequences
**Positive:**
- Replaceability becomes a side effect of narrow seams: swapping a tool,
  policy, handler, or provider is a one-call act — without a loader, without
  monkey-patching.
- Low risk: every change is a refactor with existing tests as the guard
  (`pytest` mock-LLM determinism preserved); the reactive-policy refactor
  already proved the pattern.
- Pilot seam IMPLEMENTED: compress prompt moved into
  `ContextMetricPolicy.COMPRESS_PROMPT`, private `agent._archived_artifact_ids`
  reach replaced with public `Agent.record_archived_artifact`,
  `usage_summary` moved onto public `Agent.usage_summary`; dead surface
  `ToolContext.message_count` removed; `pytest` green (466 passed).
- One canonical map: `Runtime.installed_components()` + `EventBus.handler_counts()`
  answer "what the host accepts" without registry-internal reach.

**Negative:**
- Slower to see a "capability" land (structural work, not features).
- Requires discipline to avoid churning interfaces for their own sake
  (explicit non-goal: reshuffling without coupling reduction).
- The ~7 count must be held stable while couplings are removed — refactors
  narrow or trade shapes, never add contracts.

## Verification
- Success criteria (INVESTIGATION §Success criteria): (1) the count holds ≈7;
  (2) no outside private-state reach (`rg "\._agent\b"` in `core/tools/` +
  `core/tool_context.py` → only public methods/properties); (3) one canonical
  map (`Runtime.installed_components()`); (4) zero dead surface (every member
  of the ~7 interfaces consumed by ≥1 caller or removed — `message_count` is
  the first removed instance); (5) zero regressions — full `pytest` green
  (466 passed; two known pre-existing process-cancellation flakes pass in
  isolation); (6) no loader, ever.

## Review Trigger
Revisit if the ~7 interface count grows (a new contract is needed), if a
measured coupling reappears (outside private-state reach), or if stable
contracts make a loader worth reconsidering (then it belongs to
`../../00-intent/platform-evaluation.md`, not this item).
