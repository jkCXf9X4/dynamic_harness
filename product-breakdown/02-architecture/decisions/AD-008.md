# AD-008: Comms Layer = Swappable Routing Backend Behind One Uniform Tool Surface

## Status
Accepted

## Layer
Verification (verification-led design; the design lives in the verification
investigation that produced it)

## Context
The verified baseline is **one implicit router**: `converse` reaches any agent
by ID (`get_other_agent` → `runtime.get_agent`), gated only by target status.
There is no parent-mediation gate, no sibling-scope gate, no mailbox, no topic
registry. The four topology cells (parent-mediated, same-parent siblings, one
shared channel, topic channels) therefore cannot be toggled today; they have to
be *constructed*. The comms work was measurement-first: a verification
investigation that produced a design (the review's "verification-led design"
case).

Documented in:
- `product-breakdown/04-verification/communication-structures/INVESTIGATION.md`
  (the question and the four-topology lattice).
- `product-breakdown/04-verification/communication-structures/PLAN.md` (P0–P4
  phases, the swappable comms layer, "Mock-first determinism", success
  criteria).
- `product-breakdown/04-verification/communication-structures/context-injection-design.md`
  (envelopes not content, relevance framing, per-subscription digests,
  topic discovery/creation rules).

**Rationale basis:** DOCUMENTED — PLAN.md states the layer's shape, the
one-surface/one-backend split, and the P0–P3 implementation status explicitly.

## Decision
Build a **thin, host-agnostic communication layer** between the tools and the
runtime so the four topology cells are a **config switch — not a refactor**.
The layer exposes **ONE uniform tool surface** (`converse` / `message` / `post`
/ `channel_read` / `subscribe` / `unsubscribe` / `channels` / `channel_info`);
**only the routing backend differs per cell**. A cell switch = one config key
(or one `Runtime(comms=...)` argument). This mirrors how the codebase already
separates decision from execution (`core/policies/` objects are host-agnostic;
the runtime/agent/tools delegate to them).

Shape: `src/dynamic_harness/core/comms/` — `message.py` (CommsMessage model:
id, topic, kind, sender_id, recipients, stage, content, seq, created_at),
`backend.py` (CommsBackend base: route_message / post / subscribe / unsubscribe
/ read / channels / channel_info; watermarks per-(agent, topic), backend-owned),
`channel.py` (ChannelPolicy — creation/join authority, host-agnostic, default
parent-authorized), `digest.py` (CommsDigestPolicy, push mode), `backends/`
(relay, siblings, shared, topics), `factory.py` (build_backend — the switching
seam). Tool defs live in `core/tools/comms.py` (host wiring).

## Alternatives Considered
- **One implicit router (status quo)** — REJECTED for the experiment: the four
  topologies cannot be toggled; they have to be constructed, so a swappable
  layer is the cheapest construction.
- **Four separate tool surfaces (one per topology)** — REJECTED: the model
  would have to learn a new vocabulary per cell; the whole point is one
  vocabulary with the backend deciding who receives what.
- **Proceeding on design reasoning alone (no measurement)** — REJECTED: the
  whole item exists to avoid it — success criterion 4: "A topology (or the
  hybrid) is adopted on evidence, not on the dev investigation's design
  reasoning alone."

## Consequences
**Positive:**
- The tools an agent calls never change between cells (the model learns one
  vocabulary); the backend decides who receives what — the only thing that
  varies.
- P0 (backends) + P1 (tool surface + config switching) + P2 (push-digest
  policy) + P3 (collaboration bed) are **implemented**; P4 (real-LLM run) ran
  once (2026-09-18): `off` deadlocked (timed_out, 0 turns), `shared` completed
  correctly (40 turns / 389s / ~0.8M tokens), `topics_parent` completed
  correctly with ~6× churn (232 turns / 5.2M tokens / 765s).
- Mock-first determinism: the bed is reproducible; real-LLM spread is reported
  as variance, not asserted away.
- The deadlock mechanism is understood: blocking `converse` →
  `continue_with_input` acquires the target's `_loop_lock` and runs the whole
  re-run; channel-based topologies (non-blocking post/channel_read) are robust
  to it.

**Negative:**
- P4 is n=1 per cell, pricing unconfigured (cost $0), and the run was
  interrupted once by a kill — treat the ratios, not the absolutes, as signal
  (see IMP-001 for replicates).
- The `topics_parent` churn hypothesis (topic-policing / polling overhead) is
  untested — needs a bigger replicate budget + per-tool turn breakdown.
- Making `converse` bounded / lock-safe is a runtime design change (e.g.
  bounded wait for the target's next assistant message instead of the target's
  whole re-run), deliberately out of scope for the bed.
