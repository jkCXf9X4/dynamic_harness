# IMP-003: Equivocality Heuristic (When to Escalate to Messages vs Workspace)

## Lifecycle Stage
Proposed

## Status
Open

## Layer
Architecture

## Theme
Give a child a stated rule for deciding whether a coordination need is
equivocal (→ bounded message) or uncertain (→ workspace write/read).

## Evidence
- `product-breakdown/02-architecture/multi-agent-coordination/INVESTIGATION.md`
  §"What this does to B vs C, and what still needs investigation" —
  "**Equivocality is judged by the model.** REQ odd: how does a child *know* a
  problem is equivocal vs uncertain? Needs a stated heuristic (e.g., 'try the
  workspace first; escalate to a message only after one workspace read failed
  to disambiguate') — otherwise the bias should be workspace-first by default."
- Same file, "Investigation next steps": "[ ] Define the equivocal-vs-uncertain
  heuristic so a child knows when to write vs message (bias workspace-first by
  default)".
- AD-003 decision rule 3: "To reconcile conflicting interpretations / demand a
  revision → messages, the rich channel" — the rule exists but the trigger
  condition ("equivocal") is undefined.
- Media Richness Theory (Daft & Lengel, 1986) — the anchor: equivocal
  coordination needs rich media (messages); uncertain coordination needs only
  lean media (workspace/artifacts).

## Current Pain Or Risk
The workspace-primary decision (AD-003) depends on the model correctly
classifying coordination as equivocal vs uncertain, but no heuristic is
stated. Without one, children either over-message (reintroducing push
interruption and recipient-context consumption — the exact pollution AD-001
rejected) or under-message (equivocal disputes fester in the workspace and
escalate to the parent unnecessarily, burning L2 arbitration). The bias is
supposed to be workspace-first, but that is prompt advice, not a mechanism —
and the repo's own gap-analysis (G1) shows prompt discipline is not reliable.

## Proposed Improvement
Define and state the equivocality heuristic as a decision rule (e.g. "try the
workspace first; escalate to a message only after one workspace read failed to
disambiguate; escalate to the parent only after a bounded message exchange
failed to reconcile"), bias workspace-first by default, and encode it where
the model can act on it — as a stated rule in the collaboration policy layer
(and, if it proves reliable, as a mechanical nudge in the message/workspace
tool surface).

## Risk And Blast Radius
Low–Medium. Risk: the heuristic is wrong for a measured pattern (e.g. the
model cannot reliably distinguish equivocal vs uncertain), which would weaken
AD-003's selection rule. Blast radius: the collaboration channel behavior
(message volume, workspace usage, L2 escalation rate) — but bounded: a wrong
heuristic degrades efficiency, not safety (the workspace remains the default
source of truth; the parent still verifies). Mitigation: measure message vs
workspace usage in the comms benchmark before and after.

## Dependencies

- IMP-002 (workspace mechanics) — the heuristic's "workspace read" step needs

- IMP-001 (replicates) — provides the measurement baseline for message vs

## Task Contract Seed
- **Objective:** A stated, testable equivocality heuristic that lets a child
  decide write-vs-message-vs-escalate, biased workspace-first.
- **Scope:** the heuristic statement (workspace-first; message after one
  failed workspace read; parent after a bounded message exchange); encoding in
  the collaboration policy layer; a benchmark measurement of message vs
  workspace usage with the heuristic active.
- **Acceptance:** the heuristic is stated in the collaboration policy layer;
  a mock-LLM test shows a child choosing workspace for an uncertain need and
  message for an equivocal one; the comms benchmark records message vs
  workspace usage per cell; no regression in the `shared` cell's correctness.

## Out Of Scope
- The workspace mechanics themselves (IMP-002).
- Making the heuristic a hard mechanism (e.g. blocking messages until a
  workspace read) — that is a follow-on decision if prompt-level guidance
  proves unreliable.
