# IMP-004: The `introduce` Mechanism (B-Curated Sibling Mailbox)

## Lifecycle Stage
Proposed

## Status
Open

## Layer
Architecture

## Theme
Implement the parent's one-time `introduce` act — giving each child the other's ID plus one line of "why you might benefit" — that activates a bounded sibling channel, without the parent relaying content.

## Evidence
- `../../02-architecture/multi-agent-coordination/INVESTIGATION.md` §"Refining B: 'context over control' — the parent introduces, not mediates": "The parent does not relay content. It performs a single cheap act — giving each child the *other's ID plus one line of 'why you might benefit'* — and steps back." Static: `delegate(description, collaborate_with=[...], intro_note=...)`; dynamic: a parent tool `introduce(agent_a, agent_b, note)`. "After the injection, siblings use the existing `converse`/`continue_with_input` plumbing directly — no parent round-trip per message."
- Same file, "Investigation next steps": "[ ] Decide the `introduce` mechanism: delegation-time (`collaborate_with`) vs mid-run (`introduce` tool) vs both; define the signal-based decision rules".
- REQ-1/REQ-2 (explicit membership, default-deny — the introduction is the membership act), REQ-3 (introductions requestable and declinable), REQ-4 (`introduce` ships metadata + why only, never a payload).
- AD-002 (group = common parent + explicit membership), AD-005 (founding boundary-scoped — the parent is the only one who can introduce), AD-006 (spine — the introduction creates the link edge).

## Current Pain Or Risk
The membership model (AD-002) and founder/member facets (AD-005) are designed but not executable: no `introduce` tool, no `collaborate_with` delegation parameter, no link-edge creation in the runtime. Without the mechanism the default-deny rule (REQ-2) has no positive act to grant access — collaboration cannot start. The parent's "context over control" role (introduce, never relay) is the load-bearing distinction from rejected option A; until `introduce` exists the design cannot be validated end-to-end.

## Proposed Improvement
Implement `introduce` on the AD-006 spine: (1) delegation-time `collaborate_with=[...]` + `intro_note` on `delegate` (set the team up front); (2) a mid-run `introduce(agent_a, agent_b, note)` parent tool (adaptive introduction when the parent spots an intersection or a blocked child asks for help); (3) link-edge creation + converse-eligibility gate (`(agent_a, agent_b) in self._links`) per AD-006; (4) signal-based decision rules for when the parent introduces (child status, artifact summaries, blocked-child `ask`, scope overlap — all already visible to the parent). The injection carries sibling ID + one-line rationale + scope-norm reminder only (REQ-4); content stays in artifacts.

## Risk And Blast Radius
Medium. Risk: mis-connection (the parent's judgment runs on summaries; it can introduce children whose overlap is actually a conflict) — mitigated by REQ-3 (an introduction is an invitation, not a mandate; a child may decline; the parent can disconnect; cost of a bad hookup is one wasted message). Ghosting is cheap. Blast radius: the collaboration feature area (agent loop, converse eligibility, delegation surface) — the eligibility gate touches the core `converse` path, so a bug could block or wrongly allow sibling messaging; mitigated by the default-deny gate being additive to today's parent↔child path.
